# Visual refactor reference

The canvas interface should make revision feel like operating a well-designed instrument. Visual changes must improve orientation, state visibility, editing confidence, or conceptual persuasion.

## Hierarchy

- The concept text is primary.
- Section identity and local edit state are visible.
- Annotation and edit controls remain available without dominating.
- Proposal decisions use persistent, legible states.
- The agent handoff feels consequential and reviewable.
- Images support lineage, mechanism language, or world imagination.

## Mechanism illusion

Use physical metaphors only when behavior matches them. Knobs represent continuous values. Detents represent discrete values. Lamps show state. Doors or shutters show an execution boundary. Gears may indicate processing but should not spin continuously at distracting speed.

Avoid applying wood, brass, gauges, or rivets to arbitrary controls without functional logic. The illusion succeeds through proportion, alignment, hierarchy, and feedback more than texture.

## Themes and fields

Dark mode is default. Light mode must remain complete, not an inverted afterthought. Inputs inherit the surrounding panel hue and should not appear as white rectangles. Text contrast must remain readable. Focus states must be visible.

## Motion

Motion may:

- confirm a button press;
- reveal editor or resource ports;
- indicate an agent run;
- show a lock or decision state;
- connect cause and effect.

Respect `prefers-reduced-motion`. Never use motion to delay ordinary editing.

## Imagery

Prefer original diagrams, lineage strips, mechanism studies, and world scenes. Avoid generic robot heads, glowing brains, or neon grids. Keep sufficient negative space for text. Every image needs alt text and a conceptual caption.

## Responsive behavior

At narrow widths:

- navigation becomes a drawer;
- section tools remain reachable;
- proposal decisions remain readable;
- modals fit the viewport;
- JSON review remains usable;
- no horizontal page scrolling occurs.

## Refactor report

When visual files change, report the communication goal, affected components, responsive checks, reduced-motion behavior, and any asset additions.
