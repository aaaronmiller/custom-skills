# Dad / Mentor Weekly Report Template

## Purpose

Write a one-page progress report for Aaron's father and mentor: smart non-technical readers who care about sustained effort, career positioning, and whether the work is becoming real, finished proof.

The report is a trust-building device, not a task dump.

## Exact structure

```text
Subject: Week Ending <Month Day> -- <Compelling Theme>

Greetings,

Strategic Overview

<3-5 sentence narrative of the week. Explain what kind of week it was and why it matters.>

Active Project Pipeline

<Project 1 (State; Activity): One-sentence description.>
- Optional short bullets if needed

<Project 2...>

Progress This Week

<2-4 short paragraphs or bullets. Each should show action + significance.>

Mentor Feedback

<1-2 sentences. If no meeting, say so plainly.>

Next Milestone (Upcoming Week)

- <Specific verifiable action>
- <Specific verifiable action>

Career Positioning

<1 short paragraph or 1-3 bullets connecting this week to job-search/portfolio strategy.>

-A
```

## Style rules

- Target 550-750 words unless user asks for a longer report.
- Keep the sentence-level tone professional, direct, and natural.
- Translate technical terms by function: "model comparison tool" before "model-scan"; "dashboard" is okay if its purpose is clear.
- Avoid unexplained acronyms. Spell out artificial intelligence at least once if the report is formal.
- Do not over-index on tool names. Explain what the tool does.
- Avoid false completion language. Use "designed", "scaffolded", "tested", "running", "shipped" precisely.
- Avoid excessive negativity. If a project is blocked, state the blocker and next step.
- Minimize rejection notices; focus on applications, interview readiness, portfolio proof, and visibility.
- End with forward motion, not a complaint.

## Checkbox handling

Dad-facing examples usually do not use checkboxes. If the user explicitly asks for checkboxes, keep them minimal in the Active Project Pipeline. Otherwise, put detailed checkbox tracking in the personal report.

## Strong subject patterns

- `Week Ending May 31 -- Reporting Infrastructure and Model Gateway Planning`
- `Week Ending May 23 -- Dashboard Foundations: Infrastructure and Tooling Expansion`
- `Week Ending May 15 -- Gateway Testing: Design Holds Up`
- `Week Ending November 10 -- Breakthrough in AI Automation Architecture`

## Overclaiming guardrails

Use these labels consistently:

- **Shipped**: code or artifact delivered and available.
- **Running**: verified operational, scheduled, or producing output.
- **Tested**: actually executed with results.
- **Designed**: plan/spec exists; implementation may not.
- **Scaffolded**: files exist but pipeline may not have run.
- **Paused**: consciously waiting on a dependency.
- **Blocked**: cannot proceed without fix/decision.

If evidence says "no output generated", do not write "dashboard launched" or "reporting system operational."
