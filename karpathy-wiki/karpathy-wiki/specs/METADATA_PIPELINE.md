> **Prior art:** The user's Obsidian vault contains `old vault/ChetasVault PRD appendix I YAML.md`
> which spec'd LLM-based YAML frontmatter auto-repair across all vault documents.
> This pipeline extends that approach to include confidence scoring, cross-references,
> and the memvid_indices join chain.

# Metadata Pipeline Specification

## Schema per Layer

### Wiki Layer (YAML Frontmatter)

Every wiki page MUST have this frontmatter. Generated by dream agent.

```yaml
---
title: "Concept Name"
created: 2026-05-19
updated: 2026-05-19
tags: [python, async, patterns]
confidence: 0.85                     # 0.0-1.0 from deliberative refinement
status: stable | draft | needs_review | stale
sources:
  - clawmem://docid/a1b2c3           # Provenance back to ClawMem
  - clawmem://docid/d4e5f6
wikilinks:                            # Explicit cross-refs
  - concepts/async-io.md
  - concepts/event-loop.md
contradictions:                       # If applicable
  - topic: "Best async pattern"
    position_a: "asyncio (source X, 2026-01)"
    position_b: "trio (source Y, 2026-03)"
    resolution: null                  # null = unresolved
entity_types: [concept, pattern]
expires: 2027-05-19                   # Arbitrary, for staleness detection
---
```

### ClawMem Layer (SQLite)

YAML frontmatter is parsed by `gray-matter` and stored:

| SQLite Column | Source | Type |
|--------------|--------|------|
| `title` | YAML `title` or first H1 | TEXT |
| `content_type` | YAML `status` mapped to ClawMem type | TEXT ENUM |
| `metadata_json` | All other YAML fields | TEXT (JSON blob) |
| `hash` | SHA-256 of body content | TEXT (64 chars) |
| `quality_score` | Computed from structure | REAL (0-1) |
| `confidence` | YAML `confidence` | REAL (0-1) |
| `origin` | Always `wiki://pages/...` | TEXT |

### MemVid Layer (SQLite Join Table)

MemVid stores vectors + raw text chunks in `.mv2` files. Metadata is
**not embedded in the binary** — it's preserved in a SQLite join table.

The buttplug/memory schema defines:

```sql
CREATE TABLE memvid_indices (
    memvid_file TEXT NOT NULL,
    frame_index INTEGER NOT NULL,
    chunk_id TEXT NOT NULL,
    embedding_id TEXT NOT NULL,
    corpus_id TEXT NOT NULL,
    PRIMARY KEY (memvid_file, frame_index),
    FOREIGN KEY (chunk_id) REFERENCES chunks(chunk_id),
    FOREIGN KEY (embedding_id) REFERENCES embeddings(embedding_id)
);
```

**The provenance chain:**
```
MemVid frame → memvid_indices.chunk_id → chunks.metadata_json
                                           └── Full ChunkMetadata:
                                               - provenance.source_uri
                                               - identity.content_hash
                                               - graph.incoming_references
                                               - quality.confidence_score
                                               - semantic.entities, keywords
                                               - embedding.model_id, dimensions
```

The `chunks` table stores the complete ChunkMetadata object as JSON.
Every MemVid frame round-trips to full metadata through this join.

## Reading the Chain

```
User finds result in MemVid at 4096d resolution
    │
    ▼
Look up memvid_indices WHERE memvid_file=X AND frame_index=Y
    │
    ▼
Join to chunks WHERE chunk_id = memvid_indices.chunk_id
    │
    ▼
Read chunks.metadata_json → Full provenance, confidence, quality scores
    │
    ▼
metadata_json.provenance.source_uri → Original ClawMem doc or wiki page
```

## Writing the Chain

```
Session generates new knowledge
    │
    ▼
ClawMem decision-extractor hook → writes observation to vault
    │
    ▼
Dream agent reads observation via REST API
    │
    ▼
Dream agent compiles wiki page with YAML frontmatter
    (sources: ["clawmem://docid/a1b2c3"])
    │
    ▼
Dream agent writes wiki page to pages/
    │
    ▼
ClawMem watcher detects new .md → reindexes into vault
    (origin: "wiki://pages/concepts/foo.md")
    │
    ▼
Monthly MemVid encode reads ClawMem vault
    Writes .mv2 files + populates memvid_indices table:
    memvid_file, frame_index → chunk_id (from ClawMem/buttplug DB)
    │
    ▼
Every frame is now joinable back to chunks.metadata_json
```

## Metadata Preservation at Each Transition

| Transition | Metadata Preserved | Metadata Lost |
|-----------|-------------------|---------------|
| Session → ClawMem | All | None (ClawMem stores everything) |
| ClawMem → Wiki | Key claims, confidence, provenance | Raw conversation turns |
| Wiki → ClawMem (reindex) | All (round-trips through YAML) | None |
| ClawMem → MemVid | All (via memvid_indices → chunks join) | None (round-trips through SQL) |
| MemVid recall → lookup | memvid_indices → chunks.metadata_json | None (single SQL join) |
