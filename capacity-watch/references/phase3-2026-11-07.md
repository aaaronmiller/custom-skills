## What the weights mean

Codex intervals use consecutive retained monotone snapshots within the same reset instance. Reset timestamps may differ by at most 900 seconds from the first timestamp in the group. A lower stale snapshot cannot lower the anchor. Equal-percent plateaus accumulate tokens until the next increase. Calls are counted in `(anchor time, next time]`, excluding the baseline call. Saturated 100% endpoints are censored and excluded. Non-Codex limit IDs are excluded.

The token basis is uncached input plus output plus cache writes. Cache reads are excluded to match the Phase 0 anchor. Reasoning is already inside output and is not counted twice. Every model contributes a column to the interval matrix. NNLS fits all columns together, separately for five-hour and weekly quota. Column-normalized coordinate descent reports convergence and a KKT error. Rank diagnostics prevent collinear or unconstrained models from being presented as independently identifiable. `usable` means a positive identifiable converged coefficient, not a passed reconciliation gate.

A weight of 176.4 percent points per million tokens means 10,000 uncached tokens predict 1.764 points of that window, or a fraction of 0.01764. Different window sizes have different coefficients and cannot be mixed without conversion.

| Pool/window | Samples | Relative L2 fit error | RMSE, percent points |
|---|---:|---:|---:|
| codex/five_hour | 558 | 0.8683 | 1.6320 |
| codex/weekly | 138 | 0.9568 | 5.9450 |
| claude/seven_day | 2 | 0.4464 | 1.6998 |

The Codex errors remain large. Relative L2 error is the norm of the residual vector divided by the norm of the observed deltas, not a relative error on each call. RMSE is an absolute error in percent points. Per-model RMSE uses the complete interval residual for intervals containing that model; it cannot attribute error causally to one model. `samples` counts fitted intervals with that model's tokens, and `window_instances` counts distinct reset instances. These are in-sample errors. The Phase 0 10% reconciliation gate remains failed or unresolved; Phase 3 does not claim to fix it merely by adding model coefficients. Remote usage, effort differences, timestamp alignment, rounded quota and incomplete local coverage remain possible confounders.

Claude uses a single coefficient named `*` for each observed window. Its two intervals come from one seven-day instance, so the estimate is sparse and has no independent validation.

Go's known `allowance_per_list_cost` is 60 divided by the model's monthly limit. Examples: Muse 1.0, DeepSeek Flash 0.6, Argon 2.0, Kimi K3 4.0. The free entries have 0.0. The table includes only the monthly limits actually supplied by the plan. It does not invent limits for models appearing only in the second trial.

For Go, `allowance_per_million_tokens` is total allowance divided by total uncached tokens for usable ledger calls. It depends on the observed input/output/cache mix. Explicit allowance values are preferred; missing allowance may be inferred from list cost only when the plan gives a multiplier. Separate counts expose observed and inferred samples. OMP list cost is a catalog estimate, not a provider bill. Unlisted models with observed allowance can have an empirical token weight while their list-cost multiplier remains null. Models without ledger usage use the table's 3:1 input/output price prior, with no caching. The DeepSeek price prior uses peak prices; observed allowance retains the actual billed price.

`fit_rmse_allowance` measures residual allowance dollars against the empirical token slope. `formula_rmse_allowance` checks the known list-cost multiplier on rows with both values. `formula_check_samples` is that paired-row count. Null error means there was no suitable evidence, not zero error.

## What the routing numbers mean

| Field | Meaning |
|---|---|
| `lambda` | Forecast demand divided by remaining quota for the binding window, with a 0.1 floor. Free routes use 0. Exhausted or unknown paid windows are filtered. |
| `forecast_demand` | `max(0, projected - used)` from the latest assessment, in fractions of the window. Queued workload is not added again. |
| `headroom` | `max(0, 1 - used)` for the binding window. Null means request headroom is not measured. It never means unlimited. |
| `expected_quota_units` | Expected fraction of the binding window consumed by one attempt. Codex/Claude percent points are divided by 100; Go allowance is divided by 12, 30 or 60 for rolling, weekly or monthly. |
| `binding_window` | The window with the largest `expected_quota_units * lambda`. All windows must be non-exhausted and the task must fit each one. Their prices are not summed because they constrain the same usage. |
| `p_success` | Beta posterior mean for first-attempt task success. Bulk Go uses Beta(1 + valid, 1 + invalid). A transport error is invalid; transport `ok` alone is not valid. |
| `posterior` | Alpha, beta, observed success/failure counts, and prior description. No ledger call is treated as a code-review validation result. |
| `score` | `p_success / (expected_quota_units * lambda + time_weight * expected_minutes)`. Higher is preferred. The scale is relative, not a price or probability. |
| `time_weight` | Default 0.01 quota-fraction-equivalent units per minute. This is a routing preference, not a fitted constant. `--time-weight` changes it. |
| `expected_tokens`, `expected_minutes` | Trial means per attempt for bulk Go, including failed attempts. Otherwise explicit task-size/time priors. These are not per accepted chunk. |
| `rate_limit` | Raw 429 count, total observed calls, and their ratio on that exact route during the seven days ending at assessment time. Fewer than 10 calls do not activate the hard filter. |
| `filtered[].reasons` | Every applicable rejection from quality, privacy, access, rate or quota checks. Multiple reasons can apply. |

For the saved Go assessment, rolling demand is 0.39 - 0.31 = 0.08, with headroom 0.69, giving lambda about 0.116. Weekly demand is 1.272 - 0.28 = 0.992 and headroom 0.72, giving about 1.378. Monthly demand is 9.99 - 0.14 = 9.85 with headroom 0.86, giving about 11.453. After window-size conversion, monthly is the binding cost for these Go attempts. The assessment caps projections at 9.99, so this high lambda is itself capped evidence, not a precise uncensored demand estimate.

For other tasks, ARDF's index divided by 100, clipped to 0.05 through 0.95, becomes a Beta prior with strength 4. This conversion is a heuristic, not a claim that an ARDF score is a measured success probability. Matching removes the native `claude-` prefix while retaining version numbers, then uses the existing catalog matcher. Unknown task classes default to 10,000 tokens and 2 minutes. Bulk without trial evidence uses 15,000 tokens and 2 minutes. Unmeasured free-lane timing uses calibration's 6-minute prior. ARDF takes the best available effort but the selector does not choose effort.
