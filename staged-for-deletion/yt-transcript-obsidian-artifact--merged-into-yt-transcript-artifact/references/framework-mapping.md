# Framework Mapping Reference

Every major concept in the artifact needs a framework mapping.

## Default frameworks

Use these when applicable:

| Domain | Frameworks |
|---|---|
| Technical/Coding | SDLC, design patterns, debugging methodology, systems architecture |
| Academic/Research | scientific method, Bloom's Taxonomy, Toulmin argument model, CRAAP test |
| Creative/Artistic | design thinking, story structure, iterative creation |
| Business/Strategy | SWOT, OKRs, lean canvas, Porter's Five Forces |
| Personal Development | SMART goals, habit loops, cognitive behavioral models |
| Education | ADDIE, Bloom's Taxonomy, Universal Design for Learning |
| Health/Fitness | FITT principle, periodization, biomechanics |
| General | first principles, systems thinking, Occam's razor, Concept → Mechanism → Outcome |

If no named framework fits, use:

```text
Concept → Mechanism → Outcome
```

## Audience levels

- **Novice:** foundations, definitions, what-is explanations.
- **Competent:** basic implementation, steps, common use cases.
- **Proficient:** troubleshooting, optimization, pattern recognition.
- **Expert:** edge cases, theory, novel applications, meta-analysis.

## Dual-audience rule

Every deep dive must serve:
- Strategic/conceptual readers: meaning, context, implications.
- Practical/operational readers: what to do, failure modes, validation.

A good deep dive can be read as both a conceptual note and an implementation guide.
