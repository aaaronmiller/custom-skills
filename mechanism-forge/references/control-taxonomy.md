# Mechanism control taxonomy

Choose controls by semantic fit, not visual novelty.

## Discrete value controls

### Drum or roller

Best for small ordered or cyclic banks. Show the current value and at least partial neighboring values. Support arrow keys, Home/End, direct text entry, and bank regeneration. Avoid for long paragraphs.

### Detented knob

Best for 3–12 discrete states where clockwise order is meaningful. Display the value in text. Do not rely on tick position alone.

### Card, tile, plate, or cassette

Best for swappable modules with identity and metadata: artist memory, style guide, reference artifact, symbol set, model adapter, or material kit. A socket should visibly indicate compatibility and empty state.

### Selector gate

Best for routing one input among several destinations. The route should remain visible after selection.

## Continuous controls

### Fader

Best when relative amount and comparison among adjacent channels matter. Use for density, layer balance, or temporal mix.

### Continuous knob

Best when compactness matters and the value is adjusted by feel. Provide a numeric or named readout, keyboard increments, and reset.

### XY field

Best for two genuinely related dimensions such as order/chaos and sparse/dense. Avoid when independent sliders would be clearer.

## Sequence controls

### Step row

Represents discrete temporal or narrative stages. Useful for triptychs, beats, shots, movements, or fabrication passes. Each step can have lock, mute, duplicate, and variation state.

### Punch strip or scroll

Represents a longer ordered program. It can encode repeated operations, variables, or rhythm. Provide a plain list editor for accessibility.

### Timeline

Use only when duration, overlap, and ordering are central. Do not force a timeline onto unordered image variables.

## Relation and routing controls

### Patch cables

Make source-to-destination relationships explicit. Provide automatic routing, keyboard creation, labels, and a list representation. Prevent unreadable cable tangles through bundling or service views.

### Constraint links

Show that two controls share, invert, derive, or exclude values. Examples: palette inherited across frames, accent color rotated, subject preserved while action mutates.

## Binary and consequential controls

### Toggle

Persistent binary state. Label both state and effect.

### Lever

Use for mode or authority changes such as manual to autonomous, draft to final, local to remote, or private to publish. Consequence must justify the visual weight.

### Guarded button

Use for expensive, destructive, or public actions. A cover, hold gesture, or confirmation step can communicate gravity. Never guard routine iteration.

## Displays

### Gauge

Observed values: compute load, cost, confidence, queue depth, lineage distance, or novelty pressure. Do not fake precision.

### Lamp

Binary or small-state feedback: ready, locked, connected, dirty, generating, warning. Pair color with label or shape.

### Mechanical counter

Small integer settings or results: output count, sentence count, frame count, revision number. A roller can be edited with buttons and keyboard.

### Scope ring

Shows where a lock or inheritance rule applies: current frame, sequence, artist, mechanism, battle, or culture.

## Text

Text remains necessary. Use engraved labels, note plates, popovers, or service panels, but retain real editable inputs. A physical metaphor must not prevent exact entry.
