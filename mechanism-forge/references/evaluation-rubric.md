# Mechanism evaluation rubric

Score with evidence, not aesthetic impression alone.

## Semantic fit

Can a new user predict what each control changes? Do physical metaphors match value types and consequences?

## State visibility

Are current values, locks, delegation, routes, provider, cost, and execution state visible without opening hidden menus?

## Controlled authorship

Can the user directly author, select from a bank, delegate, randomize within constraints, lock, mutate, and reclaim control? Do custom values survive regeneration?

## Spatial consistency

Do analogous controls occupy analogous positions across mechanisms? Are high-frequency and high-consequence controls placed appropriately?

## Cultural integration

Does the culture affect actual options, limits, materials, and behavior, or only the surface skin?

## Reusability

Can the mechanism serialize and restore state, change skins, change providers, and compile a provider-independent intent graph?

## Accessibility

Can all operations be completed by keyboard? Are values announced? Is reduced motion respected? Does the layout remain usable on touch and narrow screens?

## Performance

Does interaction remain responsive with large banks and histories? Are generation calls explicit, cancellable, and bounded?

## Output quality

Do changes to controls produce legible changes in generated artifacts? Do locks and inheritance behave exactly? Does provenance identify mechanism state?

## Test method

Use prediction tests, task completion, serialized-state round trips, lock stress tests, custom-value tests, provider swaps, responsive screenshots, keyboard-only runs, and at least one complete generation cycle.
