## 5. Design decisions a reviewer should know

1. **Every move needs all seven artifacts and an approval**, held or not
   (stricter than DA-032).
2. **The skill never runs a real move.** The human runs the printed commands,
   then `archive.py verify` records the move only if the checks pass. Sandbox
   execution needs the marker file, which only the fixture builders create.
3. **The archive index goes beside the folder**
   (`<archive root>/<project>/ARCHIVE-INDEX-<folder>.md`), not inside it as the
   foundation plan says, because a new file inside would change the folder's
   bytes and its `git status`, which DA-033 requires to stay the same.
4. **No `git diff`.** It rewrites `.git/index` even with
   `GIT_OPTIONAL_LOCKS=0` (found by test); the skill hashes the content of the
   paths `git status` lists instead.
5. **Cross-filesystem moves are refused**, because `mv` deletes the source after
   copying and the rule is "move, never delete".
6. **Approval signatures are not checked.** The approval file must name the
   exact source and destination and an approver; Ed25519 signature checking (as
   in T009) needs a library outside the standard library and belongs to the
   agent's policy layer.

## 6. What a human must confirm before real use

1. **The approval format and who signs it.** Decide whether the agent's T009
   operator signature must wrap the approval file, and add that check in the
   agent before it calls the skill.
2. **The consumer roots.** Point `--roots` at the real catalog.json, index.html,
   assignment-library index, plan-lineage `repos.json` and `links.json`, Living
   Documents `source-root` fields, skillshare config and the code roots, and add
   `--crontab`. The skill finds only what it is shown; raise `--max-bytes` for
   large transcripts or accept them as listed but not scanned.
3. **The index location** (decision 3 above), and the archive layout
   `~/archive/<project>/<folder>` from the foundation plan.
4. **The discovery exclusion in the real tools.** `discovery.py` proves it on
   the config it is given. Each real indexer (catalogs, plan-lineage, the
   agent's own discovery) must exclude `~/archive` in its own settings.
5. **The Living Documents page and audit.** `link --apply` appends Markdown to
   a page after a backup; if Living Documents v2 needs a contract-driven write
   (`ld-contract.yaml`), use the printed entry through that tool instead, and run
   its audit afterwards (Atlas's fourth post-move check, not done by this skill).
6. **Review load from the clause comparison.** Expect most rows on real folders
   to need an override or a destination (section 4.4). Decide who reviews and
   whether a model reviewer may write `overrides.json`.
7. **Windows paths.** Under `/mnt/<drive>/` the old-path link must be a
   junction made from Windows; the skill prints a note but does not build the
   command with real Windows paths.
8. **Install and register.** Copy or link the two folders to the skill path the
   agent searches (`~/.claude/skills` or `~/code/agents/skills`), run both
   `bin/contract` programs from there, then register each digest with
   `scripts/import-skill add`. The executable bit on `bin/contract` must survive
   the copy; run the scripts with `-B` so no `__pycache__` changes the digest.
9. **Leftover scratch.** `out/.scratch/` holds outputs of the test and real-data
   runs above (sandboxes, ledgers, the project-atlas plan). Nothing in it is
   needed. I did not delete it; remove it by hand after review.
