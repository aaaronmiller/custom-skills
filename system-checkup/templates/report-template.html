Windows Update

Updates fail because the build's signing certificate expired on August 11, not because of space or drivers

Every feature-update attempt dies with 0x800B0101 (CERT_E_EXPIRED). Microsoft rotated the Insider flight-signing certificate on 2026-08-11, and every channel needed to be on a renewal build by then. This machine is on 27965.1, compiled 2025-10-06. The update Windows Update keeps offering, 28020.2207 from May 29, is itself older than the renewal floor (28020.2623 on Beta 26H1, 28120.2630 on Experimental 26H1), so it can never validate. Drivers, Defender signatures and Store apps download fine because they are signed with production certificates.

The disk-space theory from August is closed: C: now has 120 GB free. Clock, time service and root store are all fine. No policy disables updates; wuauserv is simply idle on its default Manual start. The script C:\check_windows_updates_disabled.ps1 is a diagnostic, not a switch.

The route that works is an in-place upgrade from an ISO built with UUP dump. Setup validates the media's own signature, keeps apps, settings, WSL and Process Lasso, and does all of its first-phase work before any restart.

Package managers

npm still owns half the JavaScript projects, and in WSL "pnpm" quietly runs the Windows binary

WSL holds 155 node_modules trees totalling 34 GB. 68 projects use npm, 46 pnpm and 41 bun; 71 trees have not been touched in 90 days. On Windows the picture is small: 112 trees, 1.8 GB.

The PATH bug. In a WSL login shell, type -a pnpm finds only /mnt/c/Users/Administrator/AppData/Roaming/npm/pnpm. The Linux pnpm in ~/.local/share/pnpm is not on PATH, so every pnpm in WSL runs Windows Node over the 9P bridge against the Windows store. That is slow, and it splits your store across two filesystems. Fix it in ~/.zshrc and ~/.bashrc:

export PNPM_HOME="$HOME/.local/share/pnpm"
case ":$PATH:" in *":$PNPM_HOME:"*) ;; *) export PATH="$PNPM_HOME:$PATH" ;; esac

Also duplicated runtimes in WSL: Homebrew node 26.11.1 shadows apt node 22.23.3, and Homebrew Python 3.15 sits next to the system 3.12. Pick one per runtime; mise handles it per project.
